# KernelForge

C++ фреймворк для параллельных вычислений с числами произвольной точности.

Предоставляет пул памяти устройства поверх SYCL, высокоуровневые числовые
абстракции (`b_uint`) и тонкий HTTP-шлюз. Фреймворк спроектирован как
«чёрный ящик»: стабильный внешний API, параллельное ядро внутри.

## Для чего создан

Проект вырос из задачи по параллельным вычислениям. Цель - убрать
низкоуровневое управление памятью устройства (`malloc_device`, размеры
чанков, выравнивание) из прикладного кода и заменить его пулом памяти,
который выделяет чанки по мере необходимости, и числовыми типами, ведущими
себя как обычные значения.

## Архитектура

```
.
├── framework/     # ядро: память, числовые типы, рантайм
│   ├── include/kernelforge/
│   │   ├── memory/    # MemoryPool, Chunk, Allocation
│   │   ├── numeric/   # b_uint, b_int
│   │   └── runtime/   # Runtime — синглтон (sycl::queue)
│   └── src/
├── transport/     # внешний шлюз (REST через Drogon)
├── modules/       # бизнес-логика поверх фреймворка
└── main.cpp
```

- **framework** — ядро. Ничего не знает о HTTP и транспорте.
- **transport** — тонкий слой. Принимает запросы и передаёт их в `modules`.
  Сейчас REST на Drogon; в планах gRPC и другие протоколы.
- **modules** — прикладной код. Здесь живут конкретные вычисления.

## Компоненты

- `Runtime` — единая точка доступа к `sycl::queue` и пулу памяти.
- `MemoryPool` — пул памяти устройства с чанками. `malloc_device` вызывается
  редко: при первой аллокации и при исчерпании текущего чанка.
- `Allocation` — дескриптор `{chunk, offset, capacity}`. Лёгкий, копируемый.
- `b_uint` — целое беззнаковое число произвольной точности (в разработке).

## Стек

- C++23
- SYCL (AdaptiveCpp) — параллельное исполнение
- Drogon — HTTP-шлюз
- CMake + Ninja

## Сборка

```bash
git clone <repo>
cd KernelForge
cmake -S . -B build -G Ninja
cmake --build build
```

Зависимости: Drogon (`brew install drogon` на macOS), AdaptiveCpp, OpenMP.

## Статус

Ранняя стадия. Пул памяти работает; транспортный слой — каркас; арифметика
больших чисел и модули — в процессе.

## Принципы проектирования

- Никакой скрытой магии снаружи — только чистый API.
- Вся низкоуровневая работа (память, очереди, ядра) сосредоточена в `framework`.
- Код в `modules` должен читаться как обычный C++.
